# 04 — Go

Este capítulo enseña a usar interfaces pequeñas, `context`, errores y composición explícita para proteger el núcleo sin convertir cada paquete en una capa artificial.

## 1. 🎯 El problema

Un servicio Go organiza todo en `handlers`, `services`, `repositories` e `interfaces`; cada struct tiene una interfaz gemela. Aun así, el handler abre SQL y el caso de uso devuelve `sql.ErrNoRows`. La ceremonia creció, pero el detalle sigue cruzando la frontera.

## 2. 🧭 Interfaces junto al consumidor

En Go una implementación satisface una interfaz de forma implícita. Declara el contrato pequeño donde se consume:

```go
package create

type Orders interface {
    Save(ctx context.Context, order Order) error
}

type UseCase struct { orders Orders }

func New(orders Orders) UseCase { return UseCase{orders: orders} }
```

El adapter SQL no necesita declarar que implementa `Orders`; una asignación o prueba de compilación puede comprobarlo. Evita un paquete global `interfaces` que concentre contratos sin dueño. Organiza primero por capacidad y permite subpaquetes de transporte o persistencia cuando el tamaño los justifique.

## 3. 🔄 Contexto, errores y transacción

`context.Context` suele ser el primer parámetro de una operación con I/O. Transporta cancelación, deadline y valores de alcance de request; no se guarda en una struct ni se usa como bolsa de dependencias. El dominio puro puede no necesitarlo. Un adapter remoto respeta `ctx.Done()` y no reemplaza un deadline entrante por otro más largo.

Los adapters envuelven causas con `%w`; aplicación usa `errors.Is` o `errors.As` para clasificar y traduce `sql.ErrNoRows`, timeouts o códigos remotos a errores propios. Comparar textos de error rompe contratos.

```go
func InTransaction(ctx context.Context, db *sql.DB, fn func(*sql.Tx) error) error {
    tx, err := db.BeginTx(ctx, nil)
    if err != nil { return fmt.Errorf("begin: %w", err) }
    if err := fn(tx); err != nil {
        _ = tx.Rollback()
        return err
    }
    if err := tx.Commit(); err != nil { return fmt.Errorf("commit: %w", err) }
    return nil
}
```

Los repositorios de esa operación deben ejecutar sobre `tx`, no sobre `db`. El rollback diferido requiere cuidado para no ocultar el error de commit. La política decide qué agrupar; `database/sql` aporta la mecánica.

## 4. 🧩 Composición y pruebas

`main` abre el pool, valida config, construye adapters, casos de uso y servidor, y coordina cierre. Una función `build` devuelve el grafo o un error; no hace falta un contenedor global. El ownership queda visible: quien crea el pool lo cierra, y el servidor deja de aceptar tráfico antes de cancelar workers.

Un fake pequeño prueba coordinación; una prueba de tabla cubre reglas; `httptest` verifica el adapter HTTP; una base real verifica SQL y transacciones. `go test` y el detector de carreras ayudan, pero no deciden fixtures ni contratos. Mantén interfaces estrechas para que los dobles no reimplementen una base completa.

## 5. 🧰 Contraste de plataforma

| Plataforma | Qué da hecho | Qué te deja a ti | Trampa frecuente |
|---|---|---|---|
| Java | contenedor y transacciones por proxy | evitar que el framework invada núcleo | traducir cada bean a una interfaz Go |
| Node/TS | módulos y async context | validar runtime y manejar promesas | esconder transacción en contexto implícito |
| Go | interfaces implícitas, `context`, `sql.Tx`, `go test` | composición, scopes y traducción | paquetes por capa e interfaces gigantes |
| Python | protocolos y context managers | aplicar disciplina de imports | confundir duck typing con contrato probado |

## 6. ⚖️ Decisión y coste

Go favorece dependencias explícitas y contratos cercanos al consumidor. Eso reduce magia, pero aumenta wiring, propagación de contexto y manejo manual de cierre. Introduce una interfaz cuando existe un consumidor que necesita una capacidad sustituible, no para cada struct. El diseño correcto suele tener menos abstracciones y más ownership visible.

## ⚠️ Errores frecuentes

- “Toda struct necesita interfaz.” La interfaz pertenece a una necesidad del consumidor.
- “`context` reemplaza parámetros.” No debe transportar dependencias ni política oculta.
- “Retornar cualquier `error` ya desacopla.” `sql.ErrNoRows` todavía filtra infraestructura.
- “Usar `defer tx.Rollback()` resuelve todos los finales.” También debes tratar el error de commit.
- “Un paquete `internal` garantiza hexagonal.” Restringe imports externos, no la dirección interna.

## 7. ✅ Veredicto

Declara interfaces pequeñas junto al caso de uso, propaga contexto solo por operaciones, traduce errores y compón en `main`. Usa `sql.Tx` y recursos reales donde la frontera lo exige; no reproduzcas un framework con paquetes ceremoniales.
